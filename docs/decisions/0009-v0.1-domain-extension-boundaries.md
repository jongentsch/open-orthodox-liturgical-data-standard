# Decision 0009: define first-party extensions without expanding the core

- Status: accepted for Phase 2 review; fixture validation pending
- Date: 2026-08-25

## Decision

The following are first-party optional v0.1 extension domains:

- calendar rules and occurrence trace;
- lections and appointments;
- rank, basic fasting, and tone claims;
- work/expression/edition/asset catalog;
- grammatical-feature vocabularies and liturgical-day-boundary policy.

The calendar profile begins with fixed, Paschal-offset, and weekday-relative
rules referencing versioned calendar/paschalion definitions. Complex
transfer/suppression and collision logic remains outside the profile.

Lections use a small native ordered passage-segment model with a required
reference-system/versification identifier and mappings to OSIS or other external
systems. No external syntax is assumed universal.

A rank scheme minimally publishes ID, owner, immutable version, term IDs,
definitions, and localized labels. Descriptive features and cross-scheme
mappings are optional claims; operational service consequences remain engine
policy.

No production `oolds` saint/observance identity will be minted during Phase 3.
Fixtures use reserved example namespaces until registry governance and external
review exist.

## Open fixture question

Phase 3 must determine the identity threshold for forefeast, afterfeast, and
leave-taking: separate observance anchor, typed cycle position, or either based
on independent names/claims in the source.

## Rejected alternatives

- all extension fields in the core record;
- OSIS coordinate strings as the only lection model;
- universal rank number or feature ladder;
- full Typikon rule DSL in v0.1;
- early central identity issuance based only on the research corpus.
